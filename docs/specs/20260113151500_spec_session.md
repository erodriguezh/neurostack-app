# Spec: Session Feature

**Pattern**: Domain aggregate with value object, use case orchestration, append-only persistence

---

## Purpose

A Session represents a completed protocol activity logged by a user. Sessions are the core metric for tracking adherence, calculating streaks, and displaying progress data.

---

## Domain Model

### Session (Aggregate Root)

```dart
// lib/features/session/domain/entities/session.dart
class Session with EntityMixin<String>, AggregateRootMixin<String> {
  final String id;              // Server-generated UUID
  final String protocolId;      // Reference to Protocol aggregate
  final DateTime completedAt;   // When session was completed (user's local time)
  final SessionDuration? duration;  // Optional duration
  final String? notes;          // Optional notes (trimmed, null if empty)
}
```

**Factory Methods:**
- `Session.create({...})` — Validates and creates new session, raises `SessionLoggedEvent`
- `Session.reconstitute({...})` — Loads from persistence without validation/events

### SessionDraft (Pre-Persistence Entity)

```dart
// lib/features/session/domain/entities/session_draft.dart
class SessionDraft {
  final String protocolId;
  final DateTime completedAt;
  final SessionDuration? duration;
  final String? notes;
  // NOTE: No id field — assigned by server on insert
}
```

**Purpose:** Intermediate object between use case and repository. Used when creating sessions where the ID is not yet known.

## Business Rules & Invariants

| ID | Rule | Enforcement | Failure Code |
|----|------|-------------|--------------|
| **INV-S1** | Session belongs to exactly one Protocol | `protocolId` is required field | N/A (field structure) |
| **INV-S2** | Timestamp cannot be in the future | `completedAt.isAfter(currentTime)` check in `Session.create()` and `SessionDraft.create()` | `Session.TimestampInFuture` |
| **INV-S3** | Duration must be positive if provided | `duration.inSeconds <= 0` check in `SessionDuration.create()` | `Session.DurationMustBePositive` |
| **INV-S4** | Timestamp cannot be more than 7 days in the past | `completedAt.isBefore(currentTime - 7 days)` check in `Session.create()` and `SessionDraft.create()` | `Session.DateTooOld` |
| **INV-S5** | Notes trimmed to null if empty | `notes?.trim().isEmpty` → `null` | N/A (auto-sanitized) |
| **INV-S6** | Sessions are immutable after creation | Repository has no `update()` or `delete()` methods | N/A (API design) |

## Repository Interface

```dart
// lib/features/session/domain/repositories/session_repository.dart
abstract interface class SessionRepository {
  /// Get single session by ID
  Future<Either<DomainFailure, Session>> getById(String id);

  /// Query sessions with optional filters (AND logic, inclusive dates)
  Future<Either<DomainFailure, List<Session>>> list({
    String? protocolId,
    DateTime? from,
    DateTime? to,
  });

  /// Create new session from draft, returns Session with server ID
  Future<Either<DomainFailure, Session>> create(SessionDraft session);
}
```

**Key Behaviors:**
- All filters combine with AND logic
- Date range filters are inclusive on both bounds
- Empty result returns empty `List<Session>`, not an error
- `create()` requires authenticated user (gets `userId` from auth context)

## Use Case: LogSessionUseCase

```dart
// lib/features/session/domain/use_cases/log_session_use_case.dart
```

**Why Use Case Exists:** Coordinates User and Session repositories with multi-step validation.

### Input Parameters

```dart
class LogSessionParams {
  final String userId;
  final String protocolId;
  final DateTime completedAt;
  final DateTime currentTime;     // Injected for testability
  final SessionDuration? duration;
  final String? notes;
}
```

### Execution Flow

```
1. Load User → UserRepository.getById(userId)
   ↓
2. Validate eligibility → user.canLogSession(protocolId, currentTime)
   - INV-U4: onboarding must be completed
   - Protocol must be in user's stack
   - INV-U5: trial expiration protocol limit
   ↓
3. Create draft → SessionDraft.create(...)
   - INV-S2: timestamp not in future
   - INV-S4: timestamp not more than 7 days in past
   ↓
4. Persist → SessionRepository.create(sessionDraft)
   ↓
5. Raise SessionLoggedEvent
   ↓
Returns: Either<DomainFailure, Session>
```

### Possible Failures (Priority Order)

1. `User.NotFound` — User doesn't exist
2. `User.OnboardingNotCompleted` — User hasn't finished onboarding
3. `User.ProtocolNotInStack` — Protocol not in user's active stack
4. `User.TooManyActiveProtocols` — Trial expired, protocol count exceeds limit
5. `Session.TimestampInFuture` — completedAt is after currentTime
6. `Session.DateTooOld` — completedAt is more than 7 days in the past
7. Infrastructure errors from repository

## Data Layer

### DTOs

#### SessionDto (Deserialization)

```dart
// lib/features/session/data/dtos/session_dto.dart
@JsonSerializable()
class SessionDto {
  @JsonKey(fromJson: _stringFromJson)
  final String id;

  @JsonKey(name: 'protocol_id', fromJson: _stringFromJson)
  final String protocolId;

  @JsonKey(name: 'user_id')
  final String userId;  // NOT included in Session domain entity

  @JsonKey(name: 'completed_at')
  final String completedAt;  // ISO 8601 string

  @JsonKey(name: 'duration_seconds')
  final int? durationSeconds;

  final String? notes;

  Either<DomainFailure, Session> toDomain();
  static SessionDto fromDomain(Session session, String userId);
}
```

- `PostgrestException` → mapped via `mapPostgrestError()`
- `AuthException` → `Session.AuthenticationFailed`
- Catch-all → `Session.UnexpectedError`
